A local, static-hostable deterministic card-game simulation lab, replay forensics suite, rank anatomy observatory, decision intelligence system, counterfactual branch lab, and **interactive player experience** built on **Intrilex Engine v4.2.6** under **Official Rules v4.3.1**.

## What Intrilex Is

Intrilex is a **deterministic card-game laboratory** that also happens to be a **playable game**. Every match is a reproducible experiment: same seed + same commands = same result, verified across Node.js, browser main thread, and Web Worker.

The product is organized into three lanes:

| Lane | Description | Routes |
|------|-------------|--------|
| **Play** | Local, ranked, tournaments, replays | `/play`, `/play/new`, `/play/academy`, `/puzzles`, `/play/replays`, `/tournaments`, `/seasons` |
| **Learn** | Academy, puzzles, rules, card reference, Field Manual | `/rules`, `/play/academy`, `/puzzles`, `/cards`, `/strategy` |
| **Lab** | Watch, Caster, Evolution, mechanics, ranks, evidence, traces, branches, diagnostics | `/watch`, `/caster`, `/evolution`, `/replays`, `/history`, `/mechanics`, `/synergies`, `/ranks`, `/compare`, `/traces`, `/branches`, `/diagnostics`, `/tournament`, `/evidence`, `/intelligence` |

Active Play now uses the **Homecoming rules-assisted board**: structured Action Families, exact Action Composer confirmation, board picking, visible-information suggestions, and a viewport-native battlefield. It runs through Intrilex's existing authority, AI, networking, and save contracts. See [the migration and validation guide](docs/INTRILEX_HOMECOMING.md) for architecture, checks, and retained parity fallbacks.

## Scope

Complete First Contact, bounded two-player Advanced Core, and complete Unrestricted Core are all supported and human-playable. Online 1v1 Direct Duel is supported via server-authoritative Network Authority. The canonical 3-4 player Multiplayer rules module is blocked by design.

## Evidence Snapshot

- **Certified replays:** 121 governing compatibility + 25 semantic hotfix fixtures
- **Browser parity:** Node ↔ Chromium main thread ↔ Web Worker (real CDP proof)
- **Test suite:** Run `pnpm test` for the current source; executed counts are recorded by the full self-audit.
- **Evidence epoch:** `post-rules-parity-repair-v0.28.1`
- **Self-audit:** See [generated capability truth](config/capability-truth.json) for status, source commit, audit kind, and blockers. Development checks write to `reports/local/`; release proof requires a clean source tree and `pnpm run self-audit:release`. Historical reports do not certify the current checkout.

The static deployment is generated from the browser build with source-owned compatibility stubs. Run `pnpm run build:neocities` to regenerate it and `pnpm run verify:deploy` to verify every owned file's bytes, presence, and ownership. The check fails on modified or missing runtime files as well as stale bundles; hosting extras (`404.html`, `_headers`, and custom fonts) retain separate ownership.

Release CI checks the committed deployment against its fresh build. Configure the GitHub repository variables `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` to match the browser-safe production configuration used for the committed mirror. CI pins the production WebSocket URL to `wss://match.intrilex.cards`. Server-only keys and the operator status token belong exclusively in the match-server environment.
