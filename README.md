Every Intrilex match is a reproducible experiment: **same seed + same commands = same result**, verified across Node.js, the browser main thread, and Web Workers with real Chromium CDP proof. The lab ships a complete player experience — local play, ranked online duels, tournaments, spectator mode — alongside a research suite for replay forensics, decision intelligence, counterfactual analysis, and strategy science.

> **Product truth:** Capability claims in this README are verified against [`config/capability-truth.json`](config/capability-truth.json), generated by `scripts/generate-capability-truth.mjs`. Run `pnpm run capability:generate` to regenerate the truth, feature matrix, and known limitations. This README is hand-maintained against that truth.

## Product Lanes

The app is organized into three lanes:

| Lane | What it does | Routes |
|------|--------------|--------|
| **Play** | Local matches, ranked duels, tournaments, replays | `/play`, `/play/new`, `/puzzles`, `/play/replays`, `/tournaments`, `/seasons` |
| **Learn** | Academy, rulebook, card reference, Field Manual | `/rules`, `/play/academy`, `/puzzles`, `/cards`, `/strategy` |
| **Lab** | Watch, Caster, Evolution, mechanics, ranks, evidence, traces, branches | `/watch`, `/caster`, `/evolution`, `/replays`, `/mechanics`, `/ranks`, `/traces`, `/branches`, `/diagnostics`, `/evidence`, `/intelligence` |

Active Play runs on the **Homecoming rules-assisted board**: structured Action Families, an exact Action Composer with confirmation, board picking, visible-information suggestions, and a viewport-native battlefield — all on top of the existing authority, AI, networking, and save contracts. See [the migration and validation guide](docs/INTRILEX_HOMECOMING.md).

## Features

### Play

- **Complete rules profiles** — Advanced Core, Unrestricted Core (hidden supers, generated effect copies, 10♦ Mimic, Sudden Death), and First Contact for tutorials, all human- and AI-playable
- **Online 1v1 Direct Duel** — server-authoritative WebSocket matches with a hidden-information firewall, idempotent submission, reconnect grace countdowns, rematch flow, and certified replays
- **Ranked ladder** — Glicko-2 ratings with RD/volatility provenance, seasons with operator provisioning, placements, leaderboards, and public player profiles
- **Tournament workspace** — AI brackets with AB/BA seat-swap fairness and post-tournament analytics
- **Spectator mode** — neutral projection (never a player's authorized view), capacity limits, and spectator discovery
- **Academy + puzzle ladder** — 5 sequential interactive lessons and progressive puzzles with progress tracking

### Lab

- **Replay Caster** — live broadcast with Ollama commentary, theatre playback, and public/omniscient viewing modes
- **Evolution Lab** — local policy series, experimental heuristic training, frozen evaluation suites, replay inspection and analytics ([guide](docs/EVOLUTION_LAB.md))
- **Strategy / Field Manual** — authorized decision evidence, maturity and opportunity-normalized timing, Profile/checkpoint comparisons, exact-state research branches, and provenance-bound guide exports ([contract](docs/STRATEGY_INTELLIGENCE.md))
- **Decision intelligence** — per-decision traces with score decomposition and rule audit
- **Counterfactual branch lab** — policy-conditioned estimates from command checkpoints
- **Rank anatomy observatory** — cohort-relative power profiles and counterfactual decision value
- **Mechanics atlas** — opportunity, usage, impact, and uncertainty per mechanic
- **Experiment presets** — reproducible experiment configurations with admissibility disclosure

### Integrity

- **Evidence epoch tagging** — every match bound to engine, authority, release, seed, and policy identity
- **Hidden information** — never on the wire, never in public replays; privacy-matrix tested
- **Secret containment** — fail-closed release gate scanning tracked files and artifacts (`pnpm run release:scan-secrets`)
- **Honest claims** — policy-strength tiers (Fixture / Baseline / Heuristic); unestablished tiers and unverified imports are labeled as such

## Quick Start

**Requirements:** Node.js ≥ 22, pnpm 10.11.0

```bash
pnpm install --offline --frozen-lockfile
pnpm run dev
```

For online play during development (dev server + match authority server on port 3099):

```bash
pnpm run dev:network
```

### CLI

```bash
# Single match
pnpm run cli -- match --profile core-advanced-authority --seed 123 --p1 score-rush --p2 control

# Campaign (100 matches, 4 workers)
pnpm run cli -- campaign --profile core-advanced-authority --matches 100 --workers 4 --p1 tempo --p2 value

# Experiment presets
pnpm run experiment:list
pnpm run experiment:run
```

## Deployment

- **Frontend:** fully static-hostable. `pnpm run build:neocities` generates the deployment mirror; `pnpm run verify:deploy` verifies every owned file's bytes, presence, and ownership.
- **Match server:** Node service deployed via the systemd units and Caddyfile in [`deploy/`](deploy/), with automated SQLite backups (`intrilex-match-backup.timer`) and structured health alerting.
- **Release CI** checks the committed deployment against a fresh build. Configure the GitHub repository variables `SUPABASE_URL` and `SUPABASE_PUBLISHABLE_KEY` for the browser-safe production configuration; CI pins the production WebSocket URL to `wss://match.intrilex.cards`. Server-only keys and the operator status token belong exclusively in the match-server environment.
- Full runbook: [docs/MULTIPLAYER_DEPLOYMENT.md](docs/MULTIPLAYER_DEPLOYMENT.md) — including ranked admission reason codes and the season provisioning CLI (`node scripts/provision-season.mjs`).

## Known Limitations

Intrilex reports its limits as precisely as its capabilities:

- **Canonical 3–4 player multiplayer** — blocked by scope freeze; online 1v1 Direct Duel *is* supported
- **Optional game modules** — blocked by scope freeze
- **Event-level state stepping** — replay stepping operates at command level
- **Lookahead / Tournament / Human-meta-proxy policy tiers** — not yet benchmarked
- **Local TTS** — deferred; textual commentary is the validated contract
- **Human validation sessions** — protocol documented, sessions not yet conducted

Full list with reason codes: [KNOWN_LIMITATIONS.md](KNOWN_LIMITATIONS.md) (auto-generated from capability truth).
