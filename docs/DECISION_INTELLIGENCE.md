# Decision Intelligence

## Overview

v0.10.0 introduces a versioned, deterministic decision-trace model for every meaningful policy frame. The goal is to make every match moment intelligible through the chain:

> match state → legal opportunity → AI alternatives → chosen action → resolution → state impact → downstream interaction → statistical evidence → exact replay checkpoint

## Decision Trace Schema

Each decision trace is a frozen, hashable record with:

| Field | Description |
|-------|-------------|
| `schemaVersion` | Semantic version of the trace schema (`2.0.0`) |
| `decisionId` | Stable hash-based ID (`DT-<hash>`) |
| `matchId` | Match identifier |
| `decisionIndex` | Index of this decision in the match |
| `checkpointHash` | Canonical command checkpoint hash |
| `seat` | Player seat (1 or 2) |
| `policyId` | Versioned policy identifier |
| `policyVersion` | Policy semantic version |
| `policyHash` | Policy implementation hash |
| `decisionKind` | `MINI_TURN`, `RESPONSE`, or `PRIVATE_CHOICE` |
| `selectionMode` | `score-ranked` or `uniform-random` |
| `phase` | Canonical phase at decision |
| `turn` | Full turn sequence number |
| `publicContext` | Redacted public context (no hidden information) |
| `authorizedContextHash` | Hash of authorized context (not exposed publicly) |
| `legalOptions` | All legal actions with scores, components, reason codes, and scoreSource |
| `selectedActionId` | The action the policy selected |
| `selectionMargin` | Score difference between selected and second-best (null for random) |
| `ownItemOnTop` | Whether the actor's item is on top of the Stack |
| `ruleAudit` | Pass/fail checks with checkId, status, observed, and evidence fields |
| `reasonCodeVocabularyHash` | Deterministic hash of the reason code vocabulary |
| `mechanicRegistryHash` | Deterministic hash of the mechanic registry |
| `traceHash` | Deterministic hash of the complete trace |

## Score Decomposition

Each legal option has a score decomposed into components:

| Component | Description |
|-----------|-------------|
| `terminal` | Win-pressure contribution (1 if action reaches goal) |
| `points` | Immediate point value |
| `resource` | Resource gain (draw, swap, recycle) |
| `tempo` | Tempo efficiency (quick timing, mini-turns) |
| `defense` | Defensive value (anchor, guard, own-top protection) |
| `synergy` | Synergy contribution (anchor value) |
| `risk` | Risk exposure (self-counter, unfavorable exchange) |

Components reconcile exactly: `score = terminal*1000 + points*30 + resource*50 + tempo*20 + defense*40 + synergy*100 - risk*200`.

When actual policy-emitted candidate scores are available, `scoreSource` is `"policy"` and the `score` field contains the real policy score. When no actual scores are provided, `scoreSource` is `"reconstructed"` and the `score` field contains the reconciled component score.

## Selection Mode

- `score-ranked`: The policy deterministically selects the highest-scoring action. `selectionMargin` is the score difference between the selected action and the second-best.
- `uniform-random`: The policy selects randomly from legal actions. `selectionMargin` is `null` — no meaningful margin exists.

## Reason Codes

A finite vocabulary of 28 reason codes replaces generic explanations. Each code has:
- A human-readable display string
- A category (terminal, resource, control, tempo, value, response, effect, advanced, heuristic, exploration, risk)

Unknown reason codes fail validation. The vocabulary hash is deterministic and versioned.

## Rule Audits

Each trace includes a `ruleAudit` object with an array of evidence-derived checks. Each check has:

| Field | Description |
|-------|-------------|
| `checkId` | Stable identifier for the check type |
| `status` | `PASS`, `FAIL`, `NOT_APPLICABLE`, or `UNAVAILABLE` |
| `observed` | The actual observed value (not a hardcoded boolean) |
| `evidence` | Description of what was observed |

No check may `PASS` based on action family alone — every `PASS` must be backed by real evidence. The `exhausted-pass-forced` check counts non-exhausted legal alternatives rather than assuming the pass was forced.

## Privacy

- Public exports redact private context while preserving explanatory value
- Public traces contain no hidden card identities, private choices, or authorized context hashes
- Trace generation does not affect policy output or canonical hashes
- Automatic priority advance is never represented as a policy decision

## Determinism

- Traces are deterministic across reruns with identical inputs
- Legal options are stably ordered by score (descending) then action ID
- Trace hashes are canonical (key-sorted JSON)

## Integration

Decision traces are generated by `runPolicyMatch` when `decisionTracesEnabled: true` is passed. This is opt-in to ensure trace generation never affects canonical output. The test suite verifies that traces can be enabled without changing `matchResultHash`, `finalStateHash`, or `replayHash`.
