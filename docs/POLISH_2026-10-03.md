## Changes and edge cases

- `EvolutionStore.open()` shares a pending physical request across concurrent
  calls. Previously two calls before the first success created two connections
  while only one was retained for `close()`. Connection delivery now checks
  request ownership; version changes close their own connection only.
- Open errors, including a synchronous host exception, release pending state
  for retry. A blocked open rejects with the existing `LAB_STORAGE_BLOCKED`
  diagnostic; a later success closes its connection. An obsolete upgrade aborts
  its transaction. Explicit close rejects pending callers with
  `LAB_STORAGE_CLOSED`, while a subsequent open remains supported.
- Research browser workers handle `messageerror` as `WORKER_MESSAGE_FAILED`
  instead of waiting for the existing 30-second timeout. Owned timers/workers
  are released through the existing completion path. Accepted records remain
  present; a missing worker result is never counted as a clean game or zero.
- A progress callback may stop a run synchronously. If it then throws, the
  settled `STOPPED` state is retained. Pre-aborted runs create no workers.
- Cockpit preference parsing accepts object-shaped data only. JSON `null`,
  arrays, primitives, invalid JSON and unknown surfaces recover to Overview.
  Valid saved surfaces and explicit `?view=` routes retain their behavior.

Public method signatures, database version/stores, policy defaults, engine
rules, scientific fingerprints, artifact hashes and import/export schemas are
preserved. New diagnostics apply only to previously unhandled failure paths.
