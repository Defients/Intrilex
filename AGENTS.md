## Known Environment Limitations
- **Browser UI smoke** (`scripts/browser-ui-smoke.mjs`) requires a Chromium binary. Without it, the script writes a FAIL report to `reports/browser-ui-smoke.json`. Do not leave orphaned `browser-ui-smoke.mjs` processes running — they will continuously overwrite the committed PASS report with FAIL, causing test 96 in `v0.10.0-behavioral.test.mjs` to fail intermittently.
- **Real-browser E2E certification** (`scripts/browser-e2e-certification.mjs`) also requires Chrome/Chromium.
- **Vendor engine directory** (`vendor/intrilex-engine-4.1.0/`) is not present in all workspaces. The integration test for 121 certified replays skips gracefully when this directory is absent.

## Network Authority (v0.23.0+)
- Server-authoritative online Direct Duel for 2 remote human players via WebSocket
- **Architecture:** Split deployment — static frontend (Neocities) + independently deployable WebSocket match server (Node host). See `docs/MULTIPLAYER_DEPLOYMENT.md` for the DigitalOcean VPS production deployment guide.
- **Production deployment:** DigitalOcean VPS (`67.205.161.16`, Ubuntu 24.04) running Caddy (TLS termination) → match server on `127.0.0.1:3099` (systemd service `intrilex-match-server`). Deploy files in `deploy/` directory. Production frontend URL: `wss://match.intrilex.cards`.
- **Match server URL config:** `apps/lab-web/src/play/network/match-server-config.js` — reads `window.__INTRILEX_CONFIG__.matchServerUrl` (build-time injected via `INTRILEX_MATCH_SERVER_URL` env var), falls back to localStorage override (validated — stale `ws://` overrides are silently discarded on HTTPS pages), then dev fallback `ws://localhost:3099` (localhost only). Returns `null` in production without config → lobby shows "Online Duel Unavailable" screen. Also exports `diagnoseConfig()` — called on app bootstrap to log structured warnings when `__INTRILEX_CONFIG__` is missing or incomplete in production.
- **Build-time injection:** `scripts/bundle.mjs` injects `matchServerUrl` into a **content-hashed** `__intrilex-config.[hash].js` file (immutable, SW cache-safe) and adds the WSS URL to CSP `connect-src`. The unhashed `__intrilex-config.js` is also written for dev-server compatibility. `scripts/dev-server.mjs` serves both hashed and unhashed paths dynamically. `scripts/sync-neocities.mjs` prunes stale hashed config files on deploy.
- **CSP `frame-ancestors`:** Removed from the `<meta>` CSP tag (ignored by browsers per CSP spec when delivered via `<meta>`). Instead, `neocities-deploy/_headers` provides it as an HTTP header (forward-compatible for Netlify/Cloudflare Pages/Vercel; Neocities ignores `_headers`). The match server's `deploy/Caddyfile.match.intrilex` sets `Content-Security-Policy: frame-ancestors 'none'` via Caddy's `header` directive.
- **Production server:** `NODE_ENV=production` auto-binds to `0.0.0.0`. Respects `PORT` env var. Health endpoint at `/health` returns version + protocolVersion. Graceful shutdown via SIGTERM/SIGINT. Docker support via `Dockerfile`.
- **Packages:** `@intrilex/match-authority` (server-neutral authority), `@intrilex/network-protocol` (versioned wire protocol)
- **App:** `@intrilex/match-server` (WebSocket gateway, port 3099 in dev)

## Guest→Permanent Account Migration (v0.25+)
- **Purpose:** When a guest (anonymous) player links their Discord account, their local achievements and stats are transferred to the permanent account via the match authority server
- **Domain contracts:** `packages/account-domain/src/guest-migration.mjs` — `migrationId()`, `buildMigrationPlan()`, `validateMigrationPlan()`, `isMigrationCompleted()`, `describeMigrationStep()`; deterministic migration ID `mig_{source}_{target}`; 4 ordered steps (achievements required, stats required, ratings optional, match_history optional)
- **Supabase schema:** `supabase/migrations/0007_migration_meta.sql` — `account_migrations` table with `migration_id` PK, `source_identity`, `target_identity`, `migration_version`, `completed_at`; uniqueness constraint on (source, target, version); client writes blocked by RLS, only service role can insert
- **Protocol messages:** `MIGRATE_GUEST` (client→server) and `MIGRATION_RESULT` (server→client) in `@intrilex/network-protocol`; `validateMigrateGuest()` validates UUID source/target, non-empty achievements array, max 200 achievements; reason codes `MIGRATION_ALREADY_COMPLETED`, `MIGRATION_PLAN_INVALID`, `MIGRATION_IDENTITY_MISMATCH`
- **Server handler:** `handleMigrateGuest()` in `apps/match-server/src/server.mjs` — requires authenticated connection, verifies `conn.account.accountId === payload.targetIdentity` (security: prevents migrating to another user's account), builds deterministic migration plan, delegates to `matchResultPersistor.executeGuestMigration()`
- **Server persistence:** `SupabaseMatchResultPersistor.executeGuestMigration()` — idempotency gate via `isMigrationCompleted()`, upserts achievements to `account_achievements` with `LOCAL_DEVICE` provenance, writes `account_migrations` row; handles `23505` unique_violation as safe race condition; `FakeMatchResultPersistor.executeGuestMigration()` provides in-memory testing with `migrationCount` and `getMigration()` inspection helpers
- **Abstract interface:** `MatchResultPersistor.executeGuestMigration()` and `isMigrationCompleted()` added to the abstract base class
- **Browser auth detection:** `apps/lab-web/src/play/network/auth-controller.js` — saves guest UUID to `localStorage` key `intrilex:guest-identity` before OAuth redirect in `signInWithDiscord()`; `onAuthStateChange` callback detects ANONYMOUS→AUTHENTICATED transition and sets `_migrationPending`; exposes `isMigrationPending()`, `getGuestIdentity()`, `getAccountId()`, `clearMigrationPending()`
- **Browser migration controller:** `apps/lab-web/src/play/network/migration-controller.js` — `runMigrationIfPending()` reads local achievements from IndexedDB via `getAchievementState()`, opens short-lived WebSocket to match server, authenticates, sends `MIGRATE_GUEST`, waits for `MIGRATION_RESULT`, closes WebSocket; exposes `getMigrationStatus()`, `getMigrationResult()`, `onMigrationStatusChange()` for UI
- **Browser protocol client:** `migrateGuest()` builder added to `apps/lab-web/src/play/network/network-protocol-client.mjs`
- **UI feedback:** `apps/lab-web/src/app.js` — after `initAuth()`, checks `isMigrationPending()` and calls `runMigrationIfPending()`; shows info toast during migration, success toast with achievement count on completion, error toast on failure (local data preserved)
- **Post-migration cleanup:** `apps/lab-web/src/play/persistence.js` — `markAchievementsMigrated(migrationId)` adds `migratedAt` timestamp and `migrationId` to the IndexedDB achievement state; data is NOT deleted (kept as backup); called by migration controller after confirmed server success
- **Idempotency guarantees:** Re-running the same migration (same source→target pair) is a no-op — the server checks `account_migrations` first and returns `alreadyMigrated: true` with 0 achievements transferred; the deterministic migration ID ensures the same pair always maps to the same record
- **Security model:** The connection must be authenticated as the target identity (verified by `conn.account.accountId`); the source identity is trusted from the client (guest token may be expired after OAuth); achievements are written with `LOCAL_DEVICE` provenance (not `SERVER`); the migration record prevents replay
- **Tests:** `test/guest-migration-e2e.test.mjs` (12 tests — server integration, idempotency, auth required, identity mismatch, validation, empty achievements, same-identity rejection, conflict resolution), `test/guest-migration-plan.test.mjs` (38 tests — domain contracts, plan validation, protocol validation, guest state scenarios)

## Server-Side Achievement Evaluation (v0.24.2+)
- **Module:** `packages/match-authority/src/achievement-projection.mjs` — `evaluateMatchAchievements()` runs server-side with full engine state (no hidden-info firewall), produces per-participant unlock records
- **Protocol:** `ACHIEVEMENTS_EARNED` message (server→client) — sent after `MATCH_ENDED` + `REPLAY_AVAILABLE`; contains `unlocks[]` and `progressUpdates{}` for the individual participant
- **Server integration:** `broadcastMatchEnded()` in `server.mjs` calls `evaluateMatchAchievements()` using `match.getAuthoritativeState()` + `match.getAllEvents()`; results sent per-participant (each player only receives their own unlocks); evaluation errors are caught and logged (non-fatal)
- **Client integration:** `NetworkPlaySession` handles `ACHIEVEMENTS_EARNED` → stores `achievementUnlocks` + `achievementProgressUpdates`; `AchievementRuntime.applyServerUnlocks()` merges server unlocks into local profile (skips already-earned), persists to IndexedDB
- **Security:** Server unlocks have `provenance: NETWORK_AUTHORITY`; client merges but cannot forge server-provenance unlocks; `toCloudRow()` in achievement-sync rejects SERVER provenance from clients
- **Validation:** `ACHIEVEMENTS_EARNED` registered in `KNOWN_TYPES` in `validation.mjs`; envelope validation passes for well-formed messages
- **Server-side persistence:** `MatchResultPersistor.persistAchievementUnlocks()` writes SERVER-provenance rows to `account_achievements` via service role; called from `broadcastMatchEnded()` after evaluation; idempotent via PK `(user_id, achievement_id)`; only authenticated participants (with accountId) are persisted; fire-and-forget with error logging
- **Client wiring:** `play-app.js` calls `applyServerUnlocks()` when `networkSession.status === TERMINAL` and `achievementUnlocks.length > 0`; guarded by `state._networkAchievementsApplied` flag to prevent double-application; both initial render and `onStateChange` subscription paths handle it; toasts queued via `presenter.queueUnlocks()`
- **Tests:** `test/match-result-persistence.test.mjs` (20 tests: 13 match persistence + 7 achievement persistence + E2E), `packages/match-authority/test/smoke.test.mjs` (10 tests: 6 original + 4 achievement-projection), `packages/network-protocol/test/smoke.test.mjs` (12 tests: 10 original + 2 ACHIEVEMENTS_EARNED)
