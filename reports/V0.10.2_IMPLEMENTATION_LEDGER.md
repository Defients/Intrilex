## Phase 3 — Browser workspace liveness and exact evidence plumbing

**Status:** COMPLETE
**Scope:** Fix Traces (load shards), Branches (fixtureId/matchId), Diagnostics (stale closure), cross-workspace evidence links.
**Authority:** BL-07, BL-08, BL-09, BL-11, executable behavior.

### Changes made
1. **BL-07 fix:** `apps/lab-web/src/app.js` `renderTraces()` — was reading `r.traces` from index records (which contain only metadata: matchId, matchOrdinal, traceCount). Added `ensureTraceShardsLoaded()` async function that loads all shard files via `loadTraceData(matchId)` and caches them in `state.traceShards`. `renderTraces()` now checks if shards are loaded, shows loading state if not, then builds `allTraces` from shard data. Filters (policies, kinds, phases) are now derived from loaded trace data, not empty index metadata. Shard load errors are counted and displayed as warnings.
2. **BL-08 fix:** `apps/lab-web/src/app.js` `renderBranches()` and `runPairedCounterfactual()` — changed `retention[0].matchId` to `retention[0].fixtureId` and `r.matchId===matchId` to `r.fixtureId===matchId`. The lab-replay-index records have `fixtureId` at the top level, not `matchId`. Match selector options now use `r.fixtureId` for both value and display.
3. **BL-09 fix:** `apps/lab-web/src/app.js` `renderDiagnostics()` — the Run button's `onclick` handler was capturing `baselineId` and `candidateId` from the render-time closure. Changed to read current selector values from the DOM at click time: `document.querySelector('#diag-baseline')?.value`.
