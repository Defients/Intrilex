## Defects Fixed During Certification

1. **`legalSource` not set in viewmodel** — `buildBattlefield` was not receiving `sourceEntityIds` from legal actions, causing hand cards to not be marked as legal sources.

2. **`form` property not propagated to action contracts** — `buildAuthorizedActions` in the viewmodel was not passing the `form` property, causing all actions to be categorized as `system` timing class and filtered out by `playerGroupOrder`.

3. **`adaptSnapshotForViewModel` missing `decision` field** — The adapter was not passing through the `decision` object from the controller snapshot, causing `deriveStatus` to fall back to active player check instead of using `decision.isHuman`. This made the UI show "AI is choosing…" even when the human had a legal action in a response window.

4. **Multi-action intents with no source cards** — Intent buttons for actions with multiple options but no source card requirement were not auto-resolving. Added auto-selection of the first action when `intent.sourceCardIds.length === 0`.

5. **Save envelope hash mismatch** — The autosave was overwriting `envelope.saveId` after `getSaveEnvelope()` computed the content hash, causing the hash to no longer match. Fixed by recomputing the content hash after saveId/tutorial changes.

6. **Auto-advance card selection order** — The auto-advance was trying to click intent buttons before selecting a source card. Reordered to select a legal hand card first.

7. **Browser E2E terminal-evidence-navigation** — The `browser-e2e-certification.mjs` auto-advance was using outdated selectors that didn't handle card selection or intent buttons. Updated with the same card+intent approach.

## Local ↔ Online Presentation Parity

Both local and online matches use the same `renderActiveMatch` → `renderBoard` → `renderRankedDuel` pipeline, ensuring presentation parity. The only difference is the data source:
- **Local:** `PlaySession.getSnapshot()` (client-authoritative)
- **Online:** `NetworkPlaySession.getSnapshot()` (server-authoritative, via WebSocket)

Both produce the same authorized snapshot format that the viewmodel consumes.
