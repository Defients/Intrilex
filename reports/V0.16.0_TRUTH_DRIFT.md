## Conflicts Found

### TD-1: Variant analytics exists in code but NOT in build artifact

**Severity:** HIGH (architectural)

**Conflict:**
- `packages/analytics/src/rank-integration.mjs` exports `buildVariantAnalytics()` (line 525)
- `packages/telemetry/src/rank-telemetry.mjs` defines `VARIANT_TELEMETRY_SCHEMA_VERSION: '5.1.0'` with 25 variant metrics
- `packages/simulation-runtime/src/variant-registry.mjs` defines all 13 Spades variants and 9 Super effects
- `apps/lab-web/src/app.js` computes variant analytics at browser-runtime (line 107: `state.variantAnalytics = computeVariantAnalyticsFromSummaries(...)`)
- BUT `packages/analytics/src/analytics.mjs` `buildObservatoryAnalytics()` (line 364) does NOT call `buildVariantAnalytics()`
- The observatory artifact (`sample-data/observatory/analytics.json`) does NOT contain `variantAnalytics`
- No hash identity for variant analytics

**Resolution:** Wire `buildVariantAnalytics()` into `buildObservatoryAnalytics()` for v0.16.0. Add variant analytics to the deterministic build artifact with hash identity.

### TD-2: Duplicate buildVariantAnalytics implementations

**Severity:** MEDIUM (DRY violation)

**Conflict:**
- `apps/lab-web/src/browser-analytics.js` line 782: `export function buildVariantAnalytics({ summaries, aggregate = null, profileId = null })`
- `apps/lab-web/src/browser-rank-analytics.js` line 782: identical `export function buildVariantAnalytics({ summaries, aggregate = null, profileId = null })`
- Both are copies of the same function from `packages/analytics/src/rank-integration.mjs`

**Resolution:** Eliminate both browser copies. Use the canonical `@intrilex/analytics` export instead. The browser should consume variant analytics from the observatory artifact, not recompute it.

### TD-3: Variant telemetry schema version (5.1.0) exceeds analytics schema version (4.1.0)

**Severity:** LOW (versioning)

**Conflict:**
- `packages/telemetry/src/rank-telemetry.mjs` declares `VARIANT_TELEMETRY_SCHEMA_VERSION: '5.1.0'`
- `packages/analytics/src/analytics.mjs` declares `ANALYTICS_SCHEMA_VERSION` at 4.1.0
- The variant telemetry schema is ahead of the analytics schema, suggesting variant telemetry was added without incrementing the analytics schema

**Resolution:** Increment analytics schema version for v0.16.0 to reflect the addition of variant analytics to the build artifact.

### TD-4: Rank 2 Spades eligibility — user suspicion vs canonical authority

**Severity:** INFORMATIONAL

**Conflict:**
- User suspects Rank 2 should be excluded from independent Spades analysis
- Canonical authority (`card-face-data.js` line 132, `variant-registry.mjs` lines 23-25) declares 2♠ mechanically distinct: its Solo Wild Copy may target spade-enhanced Base modes (3♠/4♠/6♠/7♠) that 2♣/2♦/2♥ cannot copy

**Resolution:** Rank 2 IS eligible for Spades variant analysis per canonical authority. The distinction is real but subtle (wild copy targeting scope, not a unique effect mode). Display the eligibility reason transparently in the UI.

**Severity:** NONE (already fixed in prior session)

**Status:** The truth-drift guard (`scripts/truth-drift-check.mjs`) correctly verifies CI stage count, test count, and version consistency. No drift detected.
