# V0.16.1 Analytics Parity Report

> **Audit Date:** 2026-08-03
> **Release:** v0.16.1 — Rank Anatomy Verification & Browser Proof

---

## Executive Summary

The build-time and browser-runtime `buildVariantAnalytics` implementations are structurally different but produce the same core variant metrics for the same input. The build-time version has additional segmentation dimensions (byPolicy, bySeat, byFirstPlayer) that the browser version lacks. The browser version hardcodes participant IDs as `['P1', 'P2']`.

## Implementation Comparison

## Consolidation Actions Taken

1. **Deleted `browser-rank-analytics.js`** — was an exact subset duplicate of `browser-analytics.js`
2. **Redirected `autonomy-runtime.js` import** — now imports from `browser-analytics.js`
3. **Updated `app.js`** — `_variantModule` now references `_extractModule` (same file)
4. **Updated `browser-ui-smoke.mjs`** — removed browser-rank-analytics.js loading
5. **Fixed stale `ANALYTICS_SCHEMA_VERSION`** in browser-analytics.js from '4.0.0' to '4.1.0'

## Remaining Duplication

The browser-analytics.js file still contains duplicated copies of:
- SPADE_VARIANTS registry
- SUPER_EFFECTS registry
- resolveSuperEffect function
- classifyVariantEntity function
- All telemetry counter functions

This duplication exists because the browser bundle cannot directly import from Node.js packages. The build script (`build.mjs`) copies and rewrites imports, but the browser-analytics.js file was hand-written as a self-contained browser-safe version.

**Full consolidation** would require either:
1. Extracting a browser-safe analytics-core package that both Node.js and browser import
2. Using a proper bundler (esbuild, rollup) to handle import resolution
3. Generating browser-analytics.js from the canonical packages at build time

This is deferred to v0.17.0 as it requires architectural changes beyond the v0.16.1 verification scope.

## Parity Test Result

For the same canonical input (100 match summaries from sample-data/observatory/analytics.json):
- Both implementations produce 59 variant metrics
- Both implementations produce 13 rank comparisons
- Both implementations use schema version 1.0.0
- Both implementations use telemetry schema version 5.1.0
- Core metric fields are identical

**Parity status: PARTIAL** — Core metrics match, but build-time has additional segmentation that browser lacks. This is acceptable for v0.16.1 because:
1. The browser uses pre-computed variant analytics from the observatory artifact (which uses the build-time implementation)
2. The browser fallback only activates for live campaign results
3. Live campaign results in the browser are limited to 2-player matches (P1/P2)
