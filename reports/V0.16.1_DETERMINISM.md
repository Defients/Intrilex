## Determinism Verification

### Methodology

Generated the observatory analytics and Rank Anatomy registry twice from clean inputs. Computed SHA-256 hashes of the generated artifacts after each run. Compared hashes for byte identity.

### Results

| Artifact | Run 1 Hash (first 16) | Run 2 Hash (first 16) | Deterministic? |
|----------|----------------------|----------------------|----------------|
| analytics.json | b39483e5edb1fbda | b39483e5edb1fbda | YES |
| rank-anatomy-registry.json | 1c91e9c5e5a2ae89 | 1c91e9c5e5a2ae89 | YES |

### Conclusion

Both the observatory analytics and the Rank Anatomy registry are deterministic across runs. Byte identity is preserved. Timestamps are not embedded in the deterministic payload.

## Registry Hash Stability

The Rank Anatomy registry hash is computed from the canonical registry content using `hashCanonical()`. The hash is stable across invocations:

- Registry hash: 9c9a77a0611f0f3a (first 16 chars)
- This hash is embedded in the generated artifact and can be verified at load time

## Formula Registry Hash

The variant analytics includes a `metricRegistryHash` that identifies the formula registry version. This hash is stable as long as the metric definitions don't change.

## Worker Parity

The analytics build does not use parallel workers for the deterministic payload. Worker parity is not applicable for the current build pipeline.
