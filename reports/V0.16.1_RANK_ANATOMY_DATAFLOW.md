# V0.16.1 Rank Anatomy Data Flow

> **Audit Date:** 2026-08-03
> **Pipeline Stages:** 16 (engine authority → browser workspace)

---

## Pipeline Overview

```
engine authority (RANK_REGISTRY)
  → exact-card registry (card-face-data.js) [browser-only]
  → rank anatomy registry (rank-anatomy-registry.mjs)
  → variant registry (variant-registry.mjs)
  → legal opportunities (rank-attribution.mjs)
  → selected declaration (attributeAction)
  → accepted declaration (rankDecisions in runtime.mjs)
  → effect resolution (stateDelta)
  → telemetry (rank-telemetry.mjs)
  → analytics builder (buildVariantAnalytics in rank-integration.mjs)
  → analytics aggregation (buildObservatoryAnalytics in analytics.mjs)
  → generated artifact (analytics.json)
  → production build (build.mjs)
  → browser data loader (app.js boot)
  → rank anatomy workspace (rank-anatomy-workspace.js)
  → evidence deep link [NOT IMPLEMENTED]
```

## Critical Issues Found

### 1. Three duplicate buildVariantAnalytics implementations (CRITICAL)

| Location | Lines | Purpose | Used? |
|----------|-------|---------|-------|
| packages/analytics/src/rank-integration.mjs | 526-765 | Build-time (canonical) | Yes |
| apps/lab-web/src/browser-analytics.js | 782-874 | Browser runtime | Yes |
| apps/lab-web/src/browser-rank-analytics.js | 782-874 | Browser runtime (duplicate) | Loaded but duplicate |

`browser-rank-analytics.js` is an **exact duplicate** of the implementation in `browser-analytics.js`. Both contain duplicated copies of:
- SPADE_VARIANTS (lines 477-491)
- SUPER_EFFECTS (lines 493-503)
- resolveSuperEffect (lines 507-524)
- classifyVariantEntity (lines 558-593)
- All telemetry counter functions

### 2. attributeActionWithVariant exported but never called (HIGH)

`rank-attribution.mjs` exports `attributeActionWithVariant` (line 440) which classifies variant entities, but `runtime.mjs` only calls `attributeAction` (line 286). This means variant entity classification is not captured during simulation — the analytics builder must recompute it from summaries.

### 3. String-based effect classification (HIGH)

`resolveSuperEffect` uses string matching on `action.kind` and `action.mode`, with a fallback that uses substring matching (`mode.includes(s.effectId)`). This is fragile and can break if engine action schemas change.

### 4. No evidence deep link (MEDIUM)

The Evidence workspace shows authority hashes and registry info but does not implement deep linking to specific evidence records.

### 5. Source/dist divergence with no verification (HIGH)

`build.mjs` copies src to dist with manual import rewriting (lines 48-98) but does not verify that dist matches expected output. Import rewriting includes:
- scoring.mjs: Node crypto → browser SHA-256 shim
- HYBRIX modules: package imports rewritten to browser paths
- .mjs → .js in relative imports

### 6. Silently missing data (HIGH)

- `variantAnalytics` failure in `analytics.mjs` (line 367-368) only logs a warning and continues with null
- `stateDelta` may be missing from rankDecisions if resolution tracking fails
- Browser loads `rank-anatomy-registry.json` without version/hash verification

## Node Differences

### Build-time (rank-integration.mjs)
- Full participant tracking (extracts participantIds from summaries)
- Per-segment tracking (byPolicy, bySeat, byFirstPlayer)
- Profile filtering
- Uses canonical package imports

### Browser (browser-analytics.js)
- Hardcoded participantIds: `['P1', 'P2']` (line 786)
- Simplified segmentation (no byPolicy, bySeat, byFirstPlayer)
- Uses duplicated variant registry
- Stale `ANALYTICS_SCHEMA_VERSION = '4.0.0'` (line 1031)

## Resolution Plan

1. **Consolidate to one canonical implementation** — browser code should import from the canonical package, not maintain copies
2. **Delete browser-rank-analytics.js** — it is an exact duplicate of browser-analytics.js
3. **Fix browser-analytics.js** to import from canonical packages where possible
4. **Add version verification** when loading artifacts in browser
