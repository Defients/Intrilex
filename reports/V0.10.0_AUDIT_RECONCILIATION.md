# V0.10.0 Audit Reconciliation Report

## Method

Each audit claim was verified by direct source inspection. Findings are marked VERIFIED, PARTIALLY VERIFIED, or FALSE.

## Reconciliation

### 6.1 Counterfactual Branch Lab Is Not Counterfactual — VERIFIED

**Evidence:** `packages/decision-intelligence/src/counterfactual.mjs:25` calls `isCounterfactualSupported({ commands: new Array(1) }, 0)` — a fabricated one-command replay instead of the actual replay from config. Lines 44-52 run fresh matches via `runPolicyMatch` with `createSimulationState`, never restoring checkpoint state. `alternativeActionId` is used only in seed derivation (line 41) and config hashing (line 77), never in game state.

**Browser mirror:** `apps/lab-web/src/decision-intelligence.js:25` — identical bug.

**Treatment:** Rewrite `runCounterfactualBranch` to restore checkpoint state from a real replay, execute the alternative action through the engine, and continue from the post-action state. Fix paired continuation seeds to exclude the action identity.

### 6.2 Branch Comparison Is Confounded — VERIFIED

**Evidence:** `counterfactual.mjs:8` — `deriveContinuationSeed` includes `alternativeActionId` in the hash input. Selected and alternative branches therefore receive different continuation seeds, making differences unattributable.

**Treatment:** Remove `alternativeActionId` from the paired continuation seed derivation. Use `replayContentHash + decisionId + rolloutIndex + continuationPolicyIds + analysisVersion`.

### 6.3 Decision Traces Do Not Record Actual Policy Reasoning — VERIFIED

**Evidence:** `decision-trace.mjs:74-85` — `computeScoreComponents` reconstructs scores using fixed weights (`terminal*1000 + points*30 + ...`). `reconcileScore` (line 88) uses the same formula. The runtime passes `selected.metadata.candidateScores` (runtime.mjs:215) but `createDecisionTrace` never consumes them — it independently reconstructs score components.

**Treatment:** Create `DecisionEvidenceV2` contract that preserves actual policy-emitted scores. For random policies, set `selectionMode: "uniform-random"` and `selectionMargin: null`.

### 6.4 Rule Audits Contain Ceremonial PASS Results — VERIFIED

**Evidence:** `decision-trace.mjs:115` — `action.family === 'pass'` is dead code (no `'pass'` family exists; only `'exhausted-pass'`). Line 120-122: Quick marked PASS without checking actor vs active player. Line 123-125: Stack Theft target marked PASS without inspecting target.

**Treatment:** Rebuild `buildRuleAudit` to inspect actual evidence fields. Support PASS/FAIL/NOT_APPLICABLE/UNAVAILABLE.

### 6.5 Browser Policy Diagnostics Receives No Decisions — VERIFIED

**Evidence:** `worker.js:80-81` — `diagnosePolicy(summaries, [], event.data.baselinePolicyId)` passes empty decisions array. Decision count is always 0.

**Treatment:** Load actual decision data from traces or match decisions. Pass to `diagnosePolicy`.

### 6.6 Policy Diagnostics Uses Inconsistent Fields — VERIFIED

**Evidence:** `policy-diagnostics.mjs:27` uses `d.checkpointId` (trace schema uses `decisionId`). Line 34: `d.targetControllerId` and `d.actorId` — present in telemetry decisions (runtime.mjs:237-249) but not in decision traces. Line 51: `d.consumedMiniTurn` — present in telemetry decisions but not in traces.

**Treatment:** Create normalized diagnostic decision contract. Accept both telemetry decisions and trace data with explicit field mapping.

### 6.7 HYBRIX Trace Extraction Is Broken — VERIFIED

**Evidence:** `trace-adapter.mjs:24` — `decision.candidateScores?.find?.(() => false)?.hybrixTrace` — the `find` predicate `() => false` always returns undefined. Lines 232-239: maps to `COORDINATION_DIRECTIVE`, `GOAL_ORIENTED`, `TACTICAL_UTILITY`, `IDLE_ROAM`, `FALLBACK_DEFAULT` — none exist in `REASON_CODE_VOCABULARY`.

**Treatment:** Fix extraction to use actual metadata. Map to valid reason codes or add new codes to vocabulary.

### 6.8 HYBRIX Active Architecture Is Wrong Domain — VERIFIED

**Evidence:** `agent.mjs:229-254` — maps card game state to spatial entities with positions (0,0) and (20,0), health = securedPoints. Line 265: `tick(worldState, botState)` runs full perception/cognition/coordination/failsafe pipeline. Line 265 result is discarded — actual selection uses `scorePolicyAction` + personality + difficulty (lines 276-288). Cognition generates ATTACK/DEFEND/MOVE/RETREAT actions (cognition.mjs:207-260).

**Treatment:** Replace spatial pipeline with Intrilex-native cognition: authorized state interpretation → strategic posture → legal candidate scoring → personality/memory/difficulty modifiers → selection.

### 6.9 HYBRIX Benchmark Not Release-Grade — VERIFIED

**Evidence:** Not yet inspected directly. Audit claims fixed policy order, 50 games per orientation, errors as draws. To be verified during Phase 6.

**Treatment:** Build seat-balanced, uncertainty-aware benchmark runner.

### 6.10 Dependency Cycles — VERIFIED

**Evidence:**  
- `policies` → `game-ai` (package.json dep + index.mjs:3 import) and `game-ai` → `policies` (package.json dep + agent.mjs:21 import) — direct cycle  
- `decision-intelligence` → `simulation-runtime` (package.json dep + counterfactual.mjs:2 import) and `simulation-runtime` → `decision-intelligence` (package.json dep + runtime.mjs:31 import) — direct cycle  
- Transitive: `analytics` → `decision-intelligence` → `simulation-runtime` → `analytics`

**Treatment:** Extract pure contracts (score/evidence models) into lower-level packages. Use dependency injection for continuation execution.
